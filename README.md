# 접속점검 (Domain Access Check)

제휴 도메인들이 **한국에서 잘 열리는지** 자동 점검하고, **텔레그램 채널에서 전부 관리**하는 도구.
서버·요금·카드 등록 없이 **무료**로 돌아갑니다.

> **이 시스템은 외부 업체에 제공하기 위한 것입니다.** 운영자 본인의 도메인을 점검하는 다른 시스템과
> **저장소·구글시트·텔레그램 봇·채널을 절대 공유하지 않습니다.** 자세한 분리 원칙은 [SETUP.md](./SETUP.md) 0-1절.

- **담당자** — 텔레그램 채널에서 관리 (자주 쓰는 일은 버튼, 주소변경·이동 같은 건 짧은 글 명령)
- **운영자** — 구글시트 4개 탭만 보면 잘 돌고 있는지 확인 가능

## 구조

```
[텔레그램 채널]  담당자들(관리자) — 버튼으로 전부 조작
      ▲ │
 알림 │ ▼ 명령
[앱스스크립트 bridge.gs = 두뇌·무료 24시간]
      ├── 구글시트  ← 데이터 + 운영자 모니터링(접속점검·결과·이력·시스템)
      ├── 매분 트리거   ← 채널 명령 가져오기(대기조가 잘 때. 최대 1분 지연)
      ├── 매시간 트리거 ← 정해진 시각에 점검 요청(시각은 채널에서 변경 가능)
      ├── 대기조 깨우기 ──▶ [Actions relay.js] ──▶ 명령 초 단위 중계(조작할 때만)
      └── GitHub 깨우기 ──▶ [Actions + NordVPN 한국] ──▶ 점검 ──▶ 결과 회신
```

앱스스크립트는 24시간 무료로 돌지만 구글 미국 IP라 한국 접속 점검을 못 합니다.
GitHub Actions는 VPN을 붙일 수 있습니다. 그래서 **두뇌 = 앱스스크립트, 한국 IP 팔다리 = GitHub** 으로 나눴습니다.

## 담당자가 채널에서 할 수 있는 것 (전부)

| 구분 | 기능 |
|---|---|
| 도메인 | 추가(여러 개 한 번에) · 삭제 · 주소변경 · 업체간 이동 · 목록보기 |
| 업체 | 추가 · 삭제(도메인 함께) · 이름변경 |
| 점검 | 지금 점검 · 마지막 결과 다시 보기 |
| 설정 | 점검 시각 변경 · 알림 수준(항상/문제만) · 일시중지·재개 |
| 안전 | 삭제 전 확인 · **되돌리기**(직전 1회) · 변경 이력 자동 기록 |

버튼으로 하는 것: 점검·목록·추가·삭제·업체관리·설정·되돌리기·도움말.
짧은 글로 하는 것: `변경`(주소 갈아끼우기) · `이동`(업체 옮기기) · `상태`(마지막 결과 다시 보기).

**한도** — 업체 15곳 · 업체당 도메인 200개 · 업체 이름 20자 · 삭제 버튼은 한 번에 40개까지 표시(나머지는 `삭제 주소` 로).

사용법은 **[사용법-담당자용.md](./사용법-담당자용.md)** — 그대로 담당자에게 전달하면 됩니다.

## 판정

| | 뜻 |
|---|---|
| ✅ 정상 | 한국 IP로 잘 접속됨 |
| ⚠️ 제한 | 접속은 되는데 서버가 막거나 혼잡(403·429·503) — 대개 살아있음 |
| ❌ 이상 | 접속 안 됨(타임아웃·주소없음·차단451·404·서버오류) |
| 🔀 주소확인 | 열리지만 **다른 도메인으로 넘어감**(제휴 주소 변경 신호) |

## 검증

```bash
npm test          # 로직 + bridge.gs 실동작 (네트워크 불필요)
```

두 가지를 함께 돌립니다.

1. **로직 검증** — 정규화·판정·리포트·분할, 그리고 **`core.js` ↔ `bridge.gs` 도메인 규칙 대조**
   (같은 규칙이 두 곳에 있어 한쪽만 고치면 "추가는 됐는데 점검이 안 되는" 사고가 난다 → 매번 대조)
2. **bridge.gs 실동작** — 구글 API를 가짜로 만들어 앱스스크립트 코드를 그대로 실행.
   "텔레그램 명령을 넣으면 시트가 실제로 이렇게 바뀐다"를 확인.

## 세부 규칙

- **도메인 하나당 최대 30초**(15초 × 재시도 포함 상한). https 실패 시 http 로 한 번 더.
- **리다이렉트 판정**: `a.com → www.a.com` · `a.com → m.a.com` 은 **정상**(같은 사이트). `a.com → b.com` 만 🔀.
- **입력 정리**: `https://` · `www.` · 뒤 경로·포트 자동 제거, 업체 내 중복 제거, 도메인 아닌 글자 자동 제외.
- **제외된 항목은 숨기지 않는다**: 형식이 잘못돼 점검하지 못한 칸은 텔레그램 리포트와 `결과` 탭에 따로 표시된다(감시되는 줄 알고 방치하는 것을 막기 위해).
- **`결과` 탭은 매번 새로 씀**(현재 상태 스냅샷). 변경 이력은 `이력` 탭, 점검 이력은 텔레그램.
- **텔레그램 분할**: 3,500자를 넘으면 **인용블록 경계**에서 나눠 보냄(텔레그램 한도는 4,096자 — 여유를 둔 값). 서식이 깨지면 **글자만이라도 반드시 발송**한다.
- **되돌리기**는 직전 변경 1회. 한 번 더 누르면 되돌리기를 취소.

## 명령을 받는 방식 — 왜 웹훅이 아닌가

텔레그램은 웹훅(밀어주기)과 폴링(가지러 가기) 두 방식을 지원한다. **이 시스템은 폴링을 쓴다.**

앱스스크립트 웹앱은 응답으로 **302(넘김)** 를 돌려준다 — 구글이 답 본문을 다른 주소에서
내주는 구조라 피할 수 없다. 텔레그램은 302를 **실패로 판정**해 같은 명령을 계속 재시도하고,
그동안 뒤에 온 명령이 줄줄이 막힌다(2026-09-04 실측: 대기 5건,
`Wrong response from the webhook: 302 Found`). 증상은 "처음엔 되다가 점점 답이 없어짐".

그래서 방향을 뒤집었다. **대가는 최대 1분 지연, 얻는 것은 명령이 사라지지 않는 것.**

### 그 1분을 없애는 방법 — 깨우기형 대기조 (relay)

앱스스크립트 트리거는 최소 간격이 1분이라 혼자서는 더 빨라질 수 없다(하루 총 실행시간
한도 때문에 sleep 으로 쪼개는 것도 계산상 불가능). 그래서 **담당자가 첫 조작을 한 순간에만**
깃허브에서 대기조(`relay.yml` → `relay.js`)를 깨운다. 대기조는 텔레그램에 길게 귀 대고
있다가(long polling) 명령을 즉시 브리지로 넘긴다.

| 상황 | 반응 |
|---|---|
| 조용하다가 첫 조작 | 최대 1분 (대기조가 깨어나는 시간) |
| 이어지는 조작 | **2~4초** |
| 20분간 조용 | 대기조 자동 종료 → 다시 1분 방식 |

브리지 자체 처리는 0.55~2.3초(2026-09-05 실측). 최적화 전에는 7~19초였다 —
시트 읽기를 25초 캐시로 1회로 줄이고, 설정값을 요청당 한 번만 통째로 읽고,
텔레그램 두 호출을 동시에 보낸 결과다. 폴링 시절엔 1분 지연에 가려 안 보이던 비용이다.

설계 원칙 세 가지.

1. **대기조는 속도만 담당한다.** 죽어도 기능은 그대로다 — 하트비트가 90초 끊기면
   앱스스크립트 1분 폴링이 자동 복귀한다(`relayAlive_`).
2. **둘이 동시에 가져가지 않는다.** 대기조가 살아 있는 동안 `pollUpdates` 는 즉시 물러난다.
   같은 명령을 두 곳이 나눠 가지면 순서가 꼬이기 때문이다.
3. **24시간 켜두지 않는다.** 놀리는 실행을 만들지 않고, 실제 조작 시간에만 돈다.

저장소가 공개(Public)라 대기조 실행 시간은 무료다. 대신 실행 기록이 공개되므로
`relay.js` 는 **건수만** 찍고 메시지 내용·주소·업체명·chat_id·토큰을 절대 남기지 않는다
(테스트가 이를 강제한다).

## 안전장치

- **가짜 결과 방지** — 한국 IP가 아니면 점검을 건너뛰고 경고만 발송
- **무응답 감시** — 점검 요청 후 25분간 결과가 없으면 채널에 경고(조용히 죽는 것 방지)
- **권한** — 지정한 채널에서 온 명령만 실행. 미설정이면 조작 전면 거부(안전 기본값)
- **잠금** — 담당자 여러 명이 동시에 고쳐도 시트가 깨지지 않음
- **대기조 오남용 방지** — 허용된 채널에서 온 조작만 대기조를 깨운다(외부인이 깃허브 실행을 유발 불가) + 1분 쿨다운
- **자격증명 비노출** — 모든 비밀값은 GitHub 시크릿·앱스스크립트 속성에만. 코드·문서·로그에 값 0
  (단 웹앱 잠금값은 텔레그램에 등록된 웹훅 주소 안에 들어가므로, 봇 토큰이 새면 함께 새는 관계 — 둘 다 관리 대상)
- **토큰 만료 예고** — GitHub 토큰 만료 30일 전부터 채널에 알림
- **격리** — 별도 저장소·별도 시트·별도 봇. 운영자의 다른 프로젝트와 데이터가 섞이지 않음
  (단 같은 GitHub 계정에 두면 **월 실행시간 2,000분은 계정 전체가 나눠 씁니다** — 한쪽이 몰아 쓰면 다른 쪽도 멈춥니다.
   완전히 떼어내려면 이 시스템만 별도 GitHub 무료 계정에 두세요 → SETUP 12)
- **외부 의존성 0** — Node 20 내장 fetch만 사용
